Foundation

What is a Java Servlet?

A Java Servlet is a server-side Java class that handles HTTP requests and generates HTTP responses. Servlets run inside a Servlet Container (also called a Web Container) such as Apache Tomcat, Jetty, or GlassFish.

Servlets are the backbone of Java-based web applications. They receive requests from web browsers, process them (e.g. read data from a database, validate a form), and send back an HTTP response — typically HTML, JSON, or XML.

⚡

Performance

Servlets are faster than CGI scripts — they remain in memory between requests and handle multiple requests via threads.

🔒

Security

Running inside a container provides security isolation, session management, and HTTPS support out of the box.

Key Architecture Points

  • The Servlet Container manages the entire lifecycle of each Servlet
  • Each HTTP method (GET, POST, PUT, DELETE) maps to a corresponding doXxx() method
  • HttpServletRequest provides access to form data, headers, and session
  • HttpServletResponse is used to write the response body and set headers
  • The web.xml deployment descriptor (or @WebServlet annotation) maps URLs to Servlet classes
Servlet Life Cycle

From loading to destruction.

The Servlet Container fully controls the lifecycle of every Servlet. A Servlet goes through three distinct phases:

📥

Servlet Class Loaded

Container loads the Servlet class into the JVM on startup or first request

🔧

Servlet Instantiated

Container creates a single instance of the Servlet class using the default constructor

🟢

init()

Called once — Servlet initialises resources (DB connections, config loading)

⚙

service()

Called for every HTTP request — routes to doGet(), doPost(), etc.

🔁

Multiple Requests

service() handles concurrent requests via threads — one Servlet instance serves all

🔴

destroy()

Called once on shutdown — Servlet releases resources (DB connections, file handles)

🗑

Garbage Collection

Container marks the instance for garbage collection — lifecycle complete

The Three Methods

init(), service(), destroy() — explained.

init()

Initialisation Method

Called once when the Servlet is first loaded by the container. Used to set up resources that are needed for the entire lifetime of the Servlet — such as database connection pools, loading configuration files, or caching reference data.

In GreenLoop, init() would open a connection pool to the MySQL database and load the list of accepted e-waste categories from a configuration file.

When called: Once, before the first request is handled.
Signature: public void init(ServletConfig config) throws ServletException
service()

Request Handling Method

Called for every HTTP request received by the Servlet. The service() method determines the request type (GET, POST, PUT, DELETE) and delegates to the appropriate handler method.

In GreenLoop, service() would dispatch a pickup form submission (POST) to doPost(), which validates the form data, creates a booking record, and returns a JSON confirmation response.

When called: On every request — can handle concurrent requests via threads.
Signature: protected void service(HttpServletRequest req, HttpServletResponse res)
destroy()

Cleanup Method

Called once when the Servlet Container shuts down or when the Servlet is removed from service. Used to release any resources that were acquired in init() — preventing memory leaks.

In GreenLoop, destroy() would close the database connection pool and flush any pending write buffers — ensuring no data loss on shutdown.

When called: Once, when the Servlet is being removed from service.
Signature: public void destroy()
GreenLoop Application

How GreenLoop would map to Servlet architecture.

If GreenLoop were implemented as a Java EE application, each major feature would map to a dedicated Servlet class.

PickupServlet.java

Pickup Scheduling Feature

Handles POST /api/pickup/schedule — receives the pickup form data submitted by the user, validates all required fields (device type, date, address), creates a new booking record in the database via the PickupDAO class, and returns a JSON response confirming the booking reference number.

init(): Opens database connection pool, loads time slot configuration.
service(): Validates form, calls DAO, sends JSON response.
destroy(): Closes database connections.

UserServlet.java

Registration & Authentication

Handles POST /api/user/register and POST /api/user/login. For registration: validates form data, hashes the password using BCrypt, stores the new user in the database. For login: verifies credentials, creates an HttpSession, and redirects the user to their dashboard.

CatalogueServlet.java

E-Waste Catalogue API

Handles GET /api/catalogue — queries the database for the current list of accepted e-waste categories, serialises the results to JSON, and writes them to the HttpServletResponse with Content-Type: application/json. The frontend JavaScript then renders this data dynamically into the page.

ContactServlet.java

Contact Form Submission

Handles POST /api/contact — validates the contact form submission, stores the enquiry in the database, and triggers an automated email acknowledgement via the JavaMail API. Returns a success JSON response to the browser.

Technical Comparison

Servlet vs. Static Web Application.

Feature Static Web App (HTML/CSS/JS) Java Servlet Application
Processing Client-side only (browser) Server-side processing before response
Data Storage LocalStorage, SessionStorage, cookies Server-side database (MySQL, PostgreSQL)
Authentication Frontend mock / JWT validation HttpSession management — server-side sessions
Form Validation JavaScript validation only Server-side validation (cannot be bypassed)
Data Security Data visible in client code Business logic and data hidden from client
Deployment Any static file host (Netlify, GitHub Pages) Java EE server (Tomcat, Jetty, GlassFish)

Pseudocode Example

GreenLoop PickupServlet — conceptual code.

The following is illustrative pseudocode — not actual running code. It shows how GreenLoop's pickup feature would be implemented as a Java Servlet. 

// GreenLoop — PickupServlet.java (Conceptual / Pseudocode)
@WebServlet("/api/pickup/schedule")
public class PickupServlet extends HttpServlet {

  // init() — called ONCE when Servlet is loaded
  @Override
  public void init(ServletConfig config) {
    openDatabaseConnectionPool();
    loadPickupAreaConfiguration();
    System.out.println("GreenLoop PickupServlet initialised");
  }

  // service() delegates to doPost() for POST requests
  @Override
  protected void doPost(HttpServletRequest req, HttpServletResponse res) {
    String deviceType = req.getParameter("deviceType");
    String date       = req.getParameter("pickupDate");
    String address    = req.getParameter("address");

    // Validate required fields
    if (deviceType == null || date == null || address == null) {
      res.sendError(400, "Missing required pickup fields");
      return;
    }

    // Save booking to database
    Booking booking = pickupDAO.createBooking(deviceType, date, address);

    // Send JSON confirmation response
    res.setContentType("application/json");
    res.getWriter().write(
      "{\"success\": true, \"bookingId\": \"" + booking.getId() + "\"}"
    );
  }

  // destroy() — called ONCE on shutdown
  @Override
  public void destroy() {
    closeDatabaseConnectionPool();
    System.out.println("GreenLoop PickupServlet shutting down");
  }
}
